# Independent demonstration shell

Implemented: Go/Fyne v2.8.2 Russian-language window with six sections; tray Show/demo start/demo stop/Quit; close-to-tray notification; per-user/session Windows instance mutex and activation event; separate network-free mock child over bounded NDJSON; checked mock identity/version; timeout cancellation terminating the owned child; explicit demo/Degraded state; metadata creation/rename; DPAPI CurrentUser encryption API and a protected current-user Windows DACL; versioned metadata, bounded reads and atomic same-directory writes.

The GUI starts a child copy of its own executable with `--mock-core`. The independent `cmd/awg-mock-core` command is also available as an IPC test fixture. Neither imports upstream, opens proxy ports, resolves destinations or forwards traffic. The default SOCKS/HTTP addresses are labelled planned and their Copy buttons are disabled.

Storage is `%LOCALAPPDATA%/AwgLocalProxy/profiles`. Names/IDs/schema live in JSON metadata; encrypted profiles use a separate `.dpapi` blob. Demo UI imports a conservative client-only `.conf` subset into DPAPI without launching a connection or sending it to MockCore. One Interface/Peer, known fields, key encoding/length, numeric Endpoint/DNS, prefixes, MTU, keepalive and size are filtered; hooks, administrative/unknown fields, duplicate fields/sections and `.vpn` are rejected. Full-line comments are omitted; inline comments and ambiguous quoted/escaped values are rejected. Jc/Jmin/Jmax/S1–S4 require decimal uint16, H1–H4 decimal uint32. I1–I5 and H ranges are rejected until their pinned-engine grammar is validated. Accepted values are preserved; full engine compatibility/semantic validation remains deferred. Original files are retained. Only synthetic data was used in tests. Encryption failure never falls back to plaintext. DPAPI does not isolate malware running as the same user. Go cannot promise complete key erasure. Unknown metadata schema fails explicitly; no silent migration. Deleting a selected stored profile requires a confirmation and a stopped demonstration; unrelated profiles and original import files are preserved.

Incomplete: `.vpn`/`vpn://` parser, complete AWG engine validation and connecting imported profiles; asynchronous IPC event stream; actual core integration/Job Object/provenance; autostart/reconnect/sleep-resume; launch profiles. These are not claimed complete. The interface's profile selection presently selects metadata only, without changing a network backend. Existing-window activation is implemented with a per-user/session event but requires Windows manual acceptance.

Windows acceptance still required: visible rendering/tray actions and quit/parent-crash cleanup, DPI 100/125/150/200, light/dark, resize/long text/keyboard/screen reader, same-user ACL verification and cross-user DPAPI denial. Unit tests or compilation cannot establish these. No server connection or real VPN/proxy functionality has been tested.

Sources: [Fyne v2.8.2](https://github.com/fyne-io/fyne/releases/tag/v2.8.2), [UI goroutines](https://docs.fyne.io/started/goroutines/), [system tray](https://docs.fyne.io/explore/systray/), [DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata).
