# Independent GUI and core integration

The Fyne GUI has two explicit build modes. A normal `go build` has no pinned real core and starts a network-free MockCore child. `scripts/build-local.ps1` instead builds the independent core and injects its SHA-256 into the GUI. The GUI checks the adjacent executable against that hash and launches only that absolute path; a missing or mismatched core fails closed. A hash embedded in an unsigned GUI is not proof of provenance. The Windows supervisor uses a kill-on-close Job Object and inherited bounded NDJSON pipes; profile data is sent only over stdin, not arguments or environment. See `contracts/stdio-v1.md`.

The real-mode UI requires a saved non-demo profile and an explicitly entered HTTP(S) probe URL. It does not silently choose an external check service. The core uses the supplied URL through its userspace tunnel before reporting Connected. Repeat verification is user initiated; local IPC status polling does not create network probes. The displayed result is the most recent verification, not proof of continuous connectivity. SOCKS5 binds IPv4 loopback, HTTP is opt-in, and destination DNS/TCP use the userspace stack. Endpoint bootstrap DNS may use the system resolver; the current GUI importer requires a numeric endpoint.

Profiles are stored under `%LOCALAPPDATA%/AwgLocalProxy/profiles`: metadata and separate DPAPI CurrentUser encrypted blobs with restrictive current-user DACL. No plaintext fallback. The importer limits input to 8 KiB and permits one interface/peer and a conservative set of supported fields/packet sizes, including validated J/S/H/I parameters. Unknown fields, unsafe sizes, duplicate fields, executable hooks, administrative exports and `.vpn` are rejected. Full-line comments are omitted and inline comments are rejected. Original files remain untouched. Engine validation can still reject an imported profile; compatibility with a particular server is not guaranteed. DPAPI cannot defend against malware running as the same user; Go cannot guarantee complete memory erasure.

Opt-in GUI autostart uses only the current user HKCU Run entry and refuses to overwrite foreign entries. Autoconnect and bounded reconnect are separate opt-ins, disabled by default. The saved exact profile ID, explicitly chosen probe URL and ports are encrypted with DPAPI CurrentUser; a missing, demo or undecryptable profile prevents network startup. Reconnect closes the previous process before retry and does not retry permanent errors or a destination-only Degraded status. No additional probe address is selected automatically. The checkbox state and new lifecycle paths have automated tests; real user Run entries were not modified during verification.

Not yet complete: `.vpn`/`vpn://` import, all AWG 3.1 fields, explicit sleep/resume event handling, application launch profiles, continuous tunnel health detection, complete cross-user ACL/DPAPI tests, and full manual tray/DPI/accessibility acceptance. The product does not automatically change any OS network settings. The actual user's server and configuration have not been used in development tests.

The license of `synacker/amnezia-proxy` remains unresolved; its code and binaries are not incorporated. Official engine selection and release obligations are recorded in `CORE_SELECTION.md`.
