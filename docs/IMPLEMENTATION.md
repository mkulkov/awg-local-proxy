# Independent GUI and core integration

The Fyne GUI has two explicit build modes. A normal `go build` has no pinned real core and starts a network-free MockCore child. `scripts/build-local.ps1` instead builds the independent core and injects its SHA-256 into the GUI. The GUI checks the adjacent executable against that hash and launches only that absolute path; a missing or mismatched core fails closed. A hash embedded in an unsigned GUI is not proof of provenance. The Windows supervisor uses a kill-on-close Job Object and inherited bounded NDJSON pipes; profile data is sent only over stdin, not arguments or environment. See `contracts/stdio-v1.md`.

The real-mode UI requires a saved non-demo profile and an explicitly entered HTTP(S) probe URL. It does not silently choose an external check service. The core uses the supplied URL through its userspace tunnel before reporting Connected. Repeat verification is user initiated; local IPC status polling does not create network probes. The displayed result is the most recent verification, not proof of continuous connectivity. SOCKS5 binds IPv4 loopback, HTTP is opt-in, and destination DNS/TCP use the userspace stack. An ASCII VPN endpoint hostname uses the system resolver only for bootstrap; a numeric endpoint avoids this exception. The importer itself performs no DNS.

Profiles are stored under `%LOCALAPPDATA%/AwgLocalProxy/profiles`: metadata and separate DPAPI CurrentUser encrypted blobs with restrictive current-user DACL. No plaintext fallback. The importer accepts client `.conf` and selected single-profile Amnezia VPN `.vpn` exports. Client configs are limited to 8 KiB, VPN envelopes to 64 KiB and decompressed JSON to 256 KiB; one interface and one peer are supported, with a conservative validated set of AWG parameters. Only the client configuration is retained from a VPN export; administrative metadata is discarded. Subscriptions, ambiguous exports, unknown fields, unsafe sizes, duplicate fields and executable hooks are rejected. Full-line comments are omitted and inline comments are rejected. Original files remain untouched. Engine validation can still reject an imported profile; compatibility with a particular server is not guaranteed. DPAPI cannot defend against malware running as the same user; Go cannot guarantee complete memory erasure.

Opt-in GUI autostart uses only the current user HKCU Run entry and refuses to overwrite foreign entries. Autoconnect and bounded reconnect are separate opt-ins, disabled by default. The saved exact profile ID, explicitly chosen probe URL and ports are encrypted with DPAPI CurrentUser; a missing, demo or undecryptable profile prevents network startup. Reconnect closes the previous process before retry and does not retry permanent errors or a destination-only Degraded status. No additional probe address is selected automatically. The checkbox state and new lifecycle paths have automated tests; real user Run entries were not modified during verification.

Windows suspend and resume notifications stop the core and can restore a previously active connection only when reconnect is explicitly enabled; automated notification and session tests do not substitute for a physical sleep test. Application launch profiles, continuous tunnel health detection, complete cross-user ACL/DPAPI tests, and full manual tray/DPI/accessibility acceptance remain unverified or unimplemented. The product does not automatically change any OS network settings. The actual user's server and configuration have not been used in development tests.

The license of `synacker/amnezia-proxy` remains unresolved; its code and binaries are not incorporated. Official engine selection and release obligations are recorded in `CORE_SELECTION.md`.
